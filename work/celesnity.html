Celesnity

The agent loop does not talk to the outside world except through MCP. Every state change is an append-only event.

Field Agent systems
Role Designed and wrote the runtime
When Sep 2026

Context

Agent demos often paste the model, the tools, and HTTP into one place. A stuck tool stalls the web request. When the model calls the wrong tool, the record is a print statement.

Constraints

  • HTTP returns immediately. Long work stays in a worker tied to the process lifespan.
  • SQLite is the source of truth. Session state is rebuilt by replaying the log, not edited in place.
  • Swapping the mock for OpenAI must not touch the loop.
  • It has to run with no API key.

Approach

FastAPI accepts a session and a task, then queues the work. An asyncio worker runs AgentEngine in five beats: Observe, Reason, Act, Execute, Feedback. Observe rebuilds messages from the event log. Execute goes only through the MCP client, with a timeout and a circuit breaker. The event table is unique on the session and sequence pair.

The default LLM is MockLLMProvider. Telemetry spans use GenAI-like names: agent.run, llm.generate, tool.call. The loop stops after 15 iterations, and cools down when the same failure repeats.

What is true

The API can create a session, submit work, read status, cancel, and stream over SSE. The README scenarios cover a business-error recovery, a hallucinated tool, a slow MCP call, and a mid-run cancel. There is no production latency number. There are no outside users.

The queue is in memory. If the process dies after a task is accepted and before a worker runs it, that task is gone. The README states this limit.

If I continue

  1. Make the recorded task the durable unit of work, leased to workers, instead of only queueing it in RAM.
  2. Move the mock JSON-RPC onto a real MCP session lifecycle.
  3. Export OTel to Tempo and redact tool arguments that hold personal data.
