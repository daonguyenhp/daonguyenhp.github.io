OmniTrace

Drop in the trace of a run that just failed. OmniTrace finds the smallest piece that still fails, then opens a new thread with that piece removed.

Context

In a multi-step agent trace, the span that shows the failure is often not where the bad context entered. Knowing that a request was slow is not enough. You need a timeline of steps, a way to shrink the failing context, and a way to resume without that piece.

Approach

Input is one failed run as OpenTelemetry GenAI JSON (resourceSpans). Steps are spans named chat or execute_tool. A symptom is usually STATUS_CODE_ERROR. An oracle on the resource can define “still failing” (contains or tool_repeat); if it is missing, the exception message or a tool-repeat heuristic is used.

The workbench loads that file into a checkpointed timeline, runs Isolate (delta debugging / mRTF) to find the minimal failing fragment, then Fork opens a cleaned thread from the fault checkpoint with that fragment removed. Inspect is optional (logit lens / activation patching) and needs a heavier image; the free Render deploy does not enable it. The same Isolate and Fork path is also available from the CLI.

What is true

There is a public repo and a live workbench at omnitrace.onrender.com. You can drop an .otlp.json file or open a built-in sample (supply, tool-loop, overrefusal), then run Isolate and Fork in the browser. The uploaded trace stays in that session on the machine serving the page. The app is a Python HTTP server on Docker, not a static site, so it runs on Render rather than GitHub Pages.

Free Render instances sleep when idle. The first open after a pause can take about 30–60 seconds. The tutorial video slot needs examples/guide.mp4 in the deploy; without it the page shows a placeholder.
